## workflowy — Workflowy Session Logger

Claude Code 세션의 작업 내역을 Workflowy에 실시간으로 기록하고 보존한다.

### 설치

```bash
claude plugin marketplace add JeongseokChoi/j-ch-marketplace
claude plugin install workflowy@j-ch-marketplace \
  --config api_key=<WORKFLOWY_API_KEY> \
  --config root_id=<ROOT_NODE_SHORT_ID>
```

- API Key: https://workflowy.com/api-key 에서 발급
- root node short ID: Workflowy URL 끝 12자리 (`workflowy.com/#/daa0961ddeee` → `daa0961ddeee`)

### 사용

세션이 시작되면 자동으로 기록된다. 별도 조작이 필요 없다.

의미 단위 메모는 `/workflowy:session-log` 스킬이 맡는다. Claude가 계획·결정·막힌
지점을 알아서 남기고, 직접 시킬 수도 있다. 스킬 인자는 훅이 받아 바로 기록하므로
Claude 가 명령을 따로 실행하지 않는다. 직접 입력한 스킬은 턴으로 기록하지 않는다.

```
/workflowy:session-log note 인증 로직을 3단계로 분리하기로 함
/workflowy:session-log link      # 현재 세션 노드 링크
/workflowy:session-log close     # 강제 종료된 세션 수동 마감
/workflowy:session-log doctor    # 설정·연결·최근 오류 점검
```

### 기록되는 구조

```
🤖 AI                                     ← root node (설치 시 지정)
└── my-api · 2026-09-21 19:30             세션
    │   note: cwd / session id / 시작 사유
    ├── 19:30 인증 미들웨어를 verify/extract/inject 3단계로 분리했습니다. · 11분
    │   │   note: prompt: + 전체 프롬프트       턴 (끝남)
    │   ├── ▸ 계획: verify/extract/inject 3단계로 분리
    │   ├── ▸ 막힘: jwt v9에서 verify() 시그니처 변경
    │   ├── 미들웨어 구조 파악, 검증·추출·주입이 한 함수에 섞여 있음 확인
    │   ├── verify/extract/inject 로 분리, 테스트 12건 통과     정리된 목록 (턴이 끝난 뒤)
    │   └── 진행 단계 · 6                      원본 진행 단계를 옮겨 둔 곳
    │       └── 인증 미들웨어 구조 탐색 …
    ├── 19:36 🤖 Explore: Find JWT verify callers · 2분   서브에이전트 (끝남)
    │       note: 결과: (에이전트의 보고) / 지시: …
    ├── 19:38 verify() 호출부는 세 곳이고 모두 v9 시그니처로 바꿔야 합니다.
    │       note: response: + 답변 전문           보고를 받아 답한 턴
    ├── 19:41 🤖 Explore: Find JWT callers · 진행 중       서브에이전트 (일하는 중)
    ├── 19:41                                턴 (진행 중: 시각만)
    │   │   note: prompt: + 전체 프롬프트
    │   └── JWT 호출부 검색                    진행 단계 (도구가 시작될 때 추가)
    └── ⏹ 종료 · clear · 22분
```

어떤 항목도 todo 로 만들거나 완료 처리하지 않는다. 완료된 항목은 취소선에 흐려져 읽기 나쁘고,
턴은 순서대로 끝내는 과업이 아니라 시간순 기록이기 때문이다. 상태는 제목으로만 나타낸다.

턴 제목은 진행 중에는 시각만 두고, 턴이 끝나면 **Claude 응답의 첫 문장**으로 채운다.
첫 문장이 "고쳤습니다." 처럼 짧으면(20자 미만) 다음 문장을 이어 붙이고, 응답이 번호 목록으로
시작하면 첫 항목을 쓴다. 첫 줄 바로 아래에 목록이 이어지면 목록은 빼고 그 앞까지만 쓴다. 요청 전문은 노트의 `prompt:` 줄 아래에 있다. 응답을 찾지 못하면 요청 앞부분을 제목으로 쓴다. 소요 시간은 1분
이상일 때만 붙는다. 완료 알림처럼 Claude Code 가 스스로 넣는 턴은 사용자 요청이 아니므로 턴으로
기록하지 않는다. 에이전트의 보고에 답하는 턴만 예외다(아래).

Workflowy에서 root node를 열어두면, **제목이 시각뿐이거나 `· 진행 중` 이 붙은 항목이 "지금 하는
일"** 이다. 작업 중에 대기열에 넣은 요청도 바로 턴으로 추가되고, 그 요청이 실제로 처리된 턴이
끝날 때 제목이 채워진다. 처리되지 않은 턴은 다음처럼 표시된다.

| 제목 | 뜻 | 표시되는 시점 |
|---|---|---|
| ↳ 앞 요청과 함께 처리 | 앞 요청을 처리하는 도중에 전달되어 함께 처리됨 | 그 턴이 끝날 때 |
| 중단됨 | 작업 중 Esc 로 취소했거나 도구 실행을 거부함 | 입력 대기 알림 또는 다음 요청 중 먼저 오는 때 |
| 취소됨 | Claude 가 응답을 시작하기 전에 취소함 | 입력 대기 알림 또는 다음 턴이 끝날 때 |
| 처리되지 않음 | 대기열에 넣었지만 세션이 먼저 끝남 | 세션이 끝날 때 |

취소 시점에 실행되는 훅은 없다. 그래서 Claude Code 가 입력 없이 약 60초가 지나면 보내는
입력 대기 알림(`Notification` 의 `idle_prompt`)을 신호로 쓴다. 그 전까지는 취소된 턴이
진행 중처럼 보인다.

턴 아래의 불릿은 **진행 단계**다. Claude 는 도구를 부를 때마다 `description` 에 지금 하는 일을
적는데, 도구가 시작되는 순간(PreToolUse) 그 문구를 진행 중인 턴 아래에 붙인다. 세션을 시작할 때
Claude 에게 description 을 사용자 언어의 명사형으로 쓰라고 지시하므로 "설치본과 저장소 코드 비교"
처럼 남는다. description 이 없는 도구(Read·Edit·Grep 등)와 서브에이전트가 부른 도구는 붙이지 않는다.

턴이 끝나면 **결과까지 담은 목록**을 턴에 붙인다. 백그라운드에서 `claude -p --model haiku`
가 그 턴의 transcript(요청, 중간 설명, 도구 호출과 결과 일부, 최종 응답)를 읽고
"설치된 1.9.1과 저장소 코드 비교, 동일함 확인" 같은 줄로 정리한다. 원본 진행 단계는 지우지 않고
턴 맨 아래의 `진행 단계 · N` 노드 아래로 옮겨 둔다. 턴이 끝나고 10초 안팎 뒤에 바뀐다.
도구를 쓰지 않은 턴은 정리하지 않는다.

- 이 호출은 사용자의 Claude 계정으로 청구된다 (확장 사고를 끈 Haiku, 턴당 수천 토큰).
- 정리용 세션은 사용자 설정·플러그인을 읽지 않으므로 기록되지 않는다.
- 턴이 끝나자마자 세션을 닫으면 정리가 끝나지 않아 진행 단계가 턴 바로 아래에 그대로 남을 수 있다.
- 작업 중에 넣은 요청의 턴 아래 붙었던 단계도 실제로 처리한 턴의 `진행 단계` 로 모인다.
- `session-log` 스킬 호출은 `▸` 메모로 따로 남으므로 정리 입력에서 뺀다. 메모만 남긴 턴은 정리하지 않는다.
- `진행 단계` 노드의 접힘 상태는 API 로 정할 수 없어 Workflowy 의 표시 방식을 따른다.

턴 아래의 `▸` 메모는 `session-log` 스킬로 남긴 것이다. 턴은 위에서 아래로 시간순으로 읽히도록
메모, 정리된 목록, `진행 단계` 순으로 놓인다. 정리된 목록은 여러 단계를 합쳐 새로 쓴 것이라 그 안에서
메모의 자리를 알 수 없으므로, 턴 도중에 남긴 메모도 목록보다 먼저 온다.

`🤖` 항목은 Claude 가 서브에이전트에게 맡긴 일이다. 메인 세션이 에이전트에게 맡기는 순간
`… · 진행 중` 항목이 생기고, 에이전트의 보고가 도착하면 `· 진행 중` 이 소요 시간으로 바뀌며 노트
첫 줄에 **에이전트의 보고** 가 남는다. 보고를 받아 메인 세션이 한 일(번역·정리 등)은 에이전트
항목이 아니라 **메인 세션의 턴**으로 남는다. 진행 중에는 노트에 `🤖 ○○ 의 보고를 받아 작업 중` 이라
적히고, 끝나면 제목은 답변 첫 문장, 노트는 `response:` 줄 아래의 답변 전문이 된다. 어느 보고가 계기였는지는 진행 중일
때만 보인다. 답변이 여러 보고를 취합한 것일 수 있어, 끝난 뒤에는 특정 에이전트에 귀속시키지
않는다. 작업 도중에 끼어든 보고는 그 턴
안에서 처리되므로 따로 턴을 만들지 않는다. 에이전트는 턴이 끝난 뒤에도 일할 수 있으므로 턴 아래가
아니라 턴과 같은 단계에 시작 시각과 함께 둔다. 세션이 끝날 때까지 일하던 에이전트는 `· 중단됨`
으로 표시된다. 서브에이전트가 다시 띄운 에이전트는 기록하지 않는다.

실행한 명령이나 수정한 파일 경로 같은 도구 호출 자체는 기록하지 않는다. 진행 단계는 그 호출이
무엇을 위한 것인지(description)만 남긴다.

### 주의

- 프롬프트에 섞인 토큰류는 정규식으로 마스킹하지만 완전하지 않다.
  사내 토큰 형식은 `scripts/wf.py` 의 `SECRET` 패턴에 추가할 것.
- 기록 실패는 세션을 막지 않는다. 오류는 `${CLAUDE_PLUGIN_DATA}/error.log` 에 쌓이고,
  다음 세션을 시작할 때 새 오류가 있으면 Claude 가 알린다. 스킬 호출이 실패하면 그 자리에서 알린다.
- `wf.py` 는 훅 안에서만 동작한다. API key 와 기록 상태는 훅 프로세스에만 전달되기 때문이다.
  Bash 로 직접 실행하면 안내와 함께 종료한다.

### 업데이트

```bash
claude plugin update workflowy
```

유지보수자는 `plugins/workflowy/.claude-plugin/plugin.json` 의 `version` 을 올리고
push 해야 사용자에게 갱신이 전달된다.

### 제거

```bash
claude plugin uninstall workflowy
```
