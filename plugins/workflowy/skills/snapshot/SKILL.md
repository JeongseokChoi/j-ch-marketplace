# Workflowy 노드 스냅숏

인자는 훅이 먼저 처리한다: 백그라운드에서 읽기를 시작하고 `[workflowy] snapshot 시작` 으로 알린다. 읽기 명령을 따로 실행하지 않는다.
시작하지 못했으면(id 가 없거나 형식이 틀림 등) 그 이유를 사용자에게 전하고 멈춘다.

1. 훅이 알려 준 wait 명령을 Bash 의 run_in_background 로 실행하고, 사용자에게 읽는 중이라고 한 줄로 알린다.
   끝나면 결과(파일 경로와 요약, 또는 실패 이유)가 온다. wait 를 부르지 않으면 결과는 사용자의 다음 메시지 뒤에 온다.
2. 결과가 오기 전에는 파일을 읽지 않는다 (끝나기 전에는 파일이 없다).
3. 결과를 사용자에게 한 줄로 전한다. 파일을 통째로 읽지 않는다.
   id 뒤에 적힌 나머지 글은 사용자의 요청이다. 그 요청에 필요한 부분만 Grep 으로 찾고 Read 의 offset·limit 로 읽는다.

파일은 Workflowy 가 준 값만 담는다. 머리 한 줄 뒤에 한 줄에 노드 하나: `- ✓ [todo] 제목  (id: 12자리)`.
✓ 는 완료, [ ] 안은 Workflowy 의 layoutMode 원문 (없으면 붙이지 않는다), 들여쓰기가 깊이다. 첫 노드가 <id> 노드 자신이다.
그 아래 `┆` 줄은 여러 줄 제목의 나머지(코드 블록 등), `│` 줄은 note 다. 서식(굵게 등)은 빠지고 링크는 '글자 (주소)' 로 적힌다.
`[하위 못 읽음]` 이 붙은 노드는 그 아래가 빠져 있다. 같은 노드를 다시 받으면 같은 파일을 덮어쓴다.
